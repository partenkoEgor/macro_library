# macro_library

Библиотека VBA-макросов для Excel (мониторинг поддержки: статусы тикетов, TTR/FTT, эффективность сотрудников, нагрузка и зависшие тикеты, переключения, выводы, сверка Approved).

Расшифровка всех макросов для пользователей выгрузок (что делает каждый и что происходит с выгрузкой): [`docs/macros_guide.md`](docs/macros_guide.md).

Макросы независимы: каждый запускается отдельно на своей выгрузке, файл = один модуль со своими вспомогательными процедурами и обработчиком кнопок. Единственная связка — пара Approved: `Approved_Фильтр1_v3` готовит листы, которые потом читает `Approved_Перенос2_v3`.

Код лежит в `macros/` как есть, без правок, в последних присланных версиях всех 13 макросов (20.10.2026). Исключение: `Monitoring_Withdrawals.bas` (см. замечание 1). Файлы в UTF-8 без BOM (BOM из присланных файлов убран, файлы `Approved_*` присланы в Windows-1251 и перекодированы, остальное не менялось). В репозитории строки заканчиваются на LF, при checkout Git подставляет CRLF (см. `.gitattributes`).

> **Импорт в Excel.** Редактор VBA (Alt+F11 → File → Import File) читает `.bas` в кодировке Windows-1251. Если кириллица в комментариях и строках превращается в кракозябры, конвертируйте файл перед импортом:
> `iconv -f UTF-8 -t CP1251 macros/X.bas > X_cp1251.bas`.
> Или создайте модуль вручную и вставьте код через буфер обмена.

## Monitoring_Нагрузка подробнее

Запускается на книге с листом `Report` (общий экспорт). Все старые отдельные макросы теперь блоки одного модуля, их исходники в репозитории отсутствуют: `Нагрузка_API`, `Общая_нагрузка_PSP`, `Общий_мониторинг_BT_M_SMP`, `Monitoring_Зависшие_L1`, `Нагрузка_и_зависшие_Fraud`, `Зависшие_по_Гео`.

Порядок работы:

1. Удаляет свои листы из прошлых запусков и строит лист `Фильтрация`: 26 колонок из `Report`, `From` → `PS`/`User`, `Processing time` в часах. Отсчёт идёт от **максимальной `Processing date` в файле**, а не от `Now`, поэтому пороги не зависят от времени запуска. Если не найдена хоть одна из обязательных колонок, макрос останавливается со списком.
2. Считает блоки и пишет их на разные листы. У каждого блока свой список стран. Рабочая страна тикета: `Country`, если она в списке блока, иначе страна по `Ticket currency` (`L2_CountryFromCurrency`), если она в списке блока, иначе тикет в этом блоке не считается.

| Лист | Блоки |
|---|---|
| `Нагрузка L2` | API (Team A / Team B), PSP, BT M Mena 1x / Mena Leads 1x, BT M L2/L1 (агент `BankTransferAgent #279`), SMP M (13 гео) |
| `Нагрузка L1` | BT M, агент 279, 22 гео, статусы депозитов и выводов |
| `Нагрузка Fraud` | статусы Fraud, порог 24 ч и больше |
| `Зависшие тикеты` | BT M / SMP M, затем API / API без L1 / PSP |
| `ЗТ по ГЕО BT M,SMP M,PSP` | зависшие от 24 ч и больше по гео, статусам и рефералам |
| `ЗТ по ГЕО API` | гео-таблица API / PSP со списком тикетов |
| `Сводная` | 5 чисел для промежуточных отчётов 12:00 и 19:00 |
| `Вечерний отчет` | текст вечернего отчёта, один столбец, одна кнопка |
| `Неиспользуемые тикеты` | Ticket ID, не попавшие ни в один выводимый показатель: сводка и полный список |

3. Расставляет листы в порядке `Report`, `Фильтрация`, `Вечерний отчет`, `Сводная`, …, последним `Неиспользуемые тикеты`. Все пороги «Nч+» считаются как `>= N`. Итоговое сообщение показывает контроль по уникальным Ticket ID.
4. Кнопки «Копировать» вызывают `L2_CopyBlock` (адрес диапазона лежит в `AlternativeText` кнопки).

Общие вычисления BT M / SMP M делаются один раз в `L2_Btm_ComputeOnce`, результат хранится в переменных модуля `L2B_*`, `L2S_*`, `L2P_*`. Объявления стоят до первой процедуры, как требует VBA. В начале модуля есть инструкция по ручной правке гео и валют.

## Форматы исходных данных

Два макроса по сотрудникам читают лист `Sheet 1` с разной раскладкой, их нельзя менять местами:

| | `EmployeeEfficiency` | `EmployeeSwitches` |
|---|---|---|
| A | Команда | Стол |
| B | Стол | Имя |
| C | Имя | 1-е число, день |
| D… | 1-е число, день… | … |

В обоих случаях данные начинаются с 6-й строки, номер дня лежит в 4-й строке (в объединённых ячейках), тип смены («день»/«ночь») в 5-й.

Пара Approved: `Источник` — заголовки в 1-й строке («Номер заказа», «Сумма пополнения», «Статус», «ID пользователя», «ID субагента»), `Фильтр` — заголовки во 2-й строке, 1-я строка под кнопки.

## Зависимости и замечания

1. **`Monitoring_Withdrawals` в присланной версии 20.10 содержит Dominican Republic и Papua New Guinea** в геофильтре статусов 185 / 191 / 199 / 203. 30.09 они были убраны из всех списков, поэтому в репозитории оставлена версия без них. Остальной код присланной версии совпадает с репозиторием.
2. **Approved: строки 14–15 листа `Отчёт` не заполняются.** `Approved_Фильтр1_v3` (3.1.4) рассчитывает, что их заполнит `Approved_Перенос2_v3` (константа `AP3_SHEET_REPORT`), но в присланном `Перенос2` 3.1.0 такого кода нет.
3. **Approved сопоставляет `Источник` и `Фильтр` позиционно,** строка к строке, а не по номеру. Поэтому `Фильтр1` следит, чтобы в списке не было повторов Transaction ID, а `Перенос2` предупреждает, если число строк на листах разное.
4. **`fillSwitchData()` отсутствует.** `Monitoring_EmployeeSwitches` ссылается на «старый `fillSwitchData()`», который синхронизирует данные с этого листа. В репозитории его нет.
5. **`FixLatChars` в `Monitoring_TTR_FTT` объявлена как `Public`** и имеет общее имя. Если в проекте появится другая функция с таким именем, будет конфликт. Достаточно сделать её `Private` или переименовать.
6. **Комментарий про `B:AF` в `Monitoring_TicketMovements` устарел.** Реальный диапазон — `B..(MAX_DAYS+1)`. Обработчика ошибок нет: при сбое `ScreenUpdating` остаётся выключенным.
7. **Пустая замена `Replace(s, "'", "'")`** в `NormalizeKey` и `CleanText` (`Monitoring_TicketMovements`) ничего не делает. Вероятно, изначально там был типографский апостроф `’`, и он потерялся при копировании.
8. **`Monitoring_EmployeeSwitches` и `Monitoring_Filtering` без `Option Explicit`.** Остальные модули его используют. В `MsgBox` `Monitoring_Filtering` строка начинается с `?`: видимо, там был эмодзи.
9. **Жёстко зашитые значения.** Листы `Sheet 1`, `Report` и «Второй лист», списки статусов, стран, рефералов, валют, цепочек, 54 строки в `Monitoring_AgentSwitches`, Agent ID `279` (BT M). При изменении наборов правьте массивы в коде (для `Monitoring_Load` см. инструкцию в начале модуля).
10. **Все макросы пишут результат на свои листы и пересоздают их.** Исключения: `Monitoring_TTR_FTT` обновляет `Упорядоченный список` на месте, `Monitoring_StatusChains` перезаписывает только `A1:B17` листа `Результат`. `Monitoring_AgentSwitches` очищает `Результат` целиком. Не храните на этих листах ничего своего.
11. **Общие имена листов (актуально, только если запускать несколько макросов на одной книге).** `Результат` используют `Monitoring_StatusChains`, `Monitoring_AgentSwitches` и `Monitoring_Withdrawals`. `Фильтр` создают `Monitoring_Withdrawals` и `Approved_Фильтр1_v3`. `Filtered` создаёт `Monitoring_Filtering`, а `Monitoring_Зависшие_72ч` удаляет лист с этим именем. Следующий запуск затирает лист предыдущего. Если каждый макрос запускается на своей выгрузке, проблемы нет.
12. **Разная точка отсчёта `Processing time`.** `Monitoring_Load` считает от максимальной `Processing date` в выгрузке, а `Monitoring_Filtering` и `Monitoring_Зависшие_72ч` от `Now`. Из-за второго варианта пороги 72 ч и больше зависят от времени запуска.
13. **`Monitoring_API_BT_M_PSP_SMP` работает только на сырой выгрузке.** Он сравнивает `From` со значением `by customer`. На листах `Filtered` / `Фильтрация`, где `From` уже заменён на `User`/`PS`, все тикеты посчитаются как PS. Если для отдельного листа не нашлась нужная колонка (`Payment method` для API, `Agent` для SMP), этот лист не создаётся, а в конце макрос всё равно показывает «Готово!».
14. **Неиспользуемый код в `Monitoring_Load`.** Процедуры `L2_Block_Leaders`, `L2_Block_BTM_PK`, `L2_Pk_PrintBlock`, `L2_Psp_WriteStatusRows`, `L2_Block_PSP_Geo` нигде не вызываются. Листы `Лидеры` и `Сводная таблица 12-19` макрос удаляет и упорядочивает, но не создаёт.
15. **`Monitoring_AgentSwitches`.** Подсказка про вставку в Google Таблицу с `E11` зашита в сообщение. Названия стран и столов на листе `Результат` заданы в `BuildTargets`.
16. **Хранение и кнопки.** Имена публичных процедур во всех модулях уникальны, поэтому их можно держать вместе (например, в `PERSONAL.XLSB`), но это не обязательно. Кнопки хранят в `OnAction` имя книги с кодом (`ThisWorkbook.Name`). Если сохранить результат и открыть его на другом компьютере, кнопки без этой книги не сработают.
17. **`From` заменяется по-разному.** `Monitoring_Withdrawals` превращает `Through Customer Support` в `L1`. `Monitoring_Filtering` и `Monitoring_Зависшие_72ч` превращают `Through customer support` в `PS`, `By yourself` в `User`. `Monitoring_Load` и `Approved_Фильтр1_v3` дополнительно понимают новые значения `By Customer Support` → `PS` и `By customer` → `User`.
18. **`Monitoring_Withdrawals`, кнопка Ticket ID отклонённых.** Если тикетов с `Transaction Status = rejected` нет, кнопка всё равно указывает на `K2`. Последняя строка данных определяется только по столбцу A. При ошибке в середине макроса `ScreenUpdating` остаётся выключенным (обработчика ошибок нет).
19. **`Monitoring_Зависшие_72ч`, рефералы SMP** сравниваются по полному значению `Referal`. Если в выгрузке реферал приходит с номером (`webDefault #1`), такая строка не пройдёт фильтр.
