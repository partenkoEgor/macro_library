# macro_library

Библиотека VBA-макросов для Excel (мониторинг поддержки: статусы тикетов, TTR/FTT, эффективность сотрудников, нагрузка и зависшие тикеты, переключения, выводы).

Макросы независимы: каждый запускается отдельно на своей выгрузке, файл = один модуль со своими вспомогательными процедурами и обработчиком кнопок. Единственное исключение: `Monitoring_TTR_FTT` вызывает `CMB_CopyBlock`, которого в репозитории нет (см. замечание 1).

Код лежит в `macros/` как есть, без правок. Файлы в UTF-8 без BOM (у `Monitoring_API_BT_M_PSP_SMP.bas`, `Monitoring_Load.bas` и `Monitoring_Withdrawals.bas` BOM был в присланных файлах, я его убрал, остальное не менял). В репозитории строки заканчиваются на LF, при checkout Git подставляет CRLF (см. `.gitattributes`).

> **Импорт в Excel.** Редактор VBA (Alt+F11 → File → Import File) читает `.bas` в кодировке Windows-1251. Если кириллица в комментариях и строках превращается в кракозябры, конвертируйте файл перед импортом:
> `iconv -f UTF-8 -t CP1251 macros/X.bas > X_cp1251.bas`.
> Или создайте модуль вручную и вставьте код через буфер обмена.

## Monitoring_Нагрузка подробнее

Запускается на книге с листом `Report` (общий экспорт). Все старые отдельные макросы теперь блоки одного модуля, их исходники в репозитории отсутствуют: `Нагрузка_API`, `Общая_нагрузка_PSP`, `Общий_мониторинг_BT_M_SMP`, `Monitoring_Зависшие_L1`, `Нагрузка_и_зависшие_Fraud`, `Зависшие_по_Гео`.

Порядок работы:

1. Удаляет свои листы из прошлых запусков и строит лист `Фильтрация`: 26 колонок из `Report`, `From` → `PS`/`User`, `Processing time` в часах. Отсчёт идёт от **максимальной `Processing date` в файле**, а не от `Now`, поэтому пороги не зависят от времени запуска. Если не найдена хоть одна из обязательных колонок, макрос останавливается со списком.
2. Считает блоки, которые пишутся на разные листы:

| Лист | Блоки |
|---|---|
| `Нагрузка L2` | API (Team A / Team B), PSP, BT M / SMP M, BT M L2/L1 (агент `BankTransferAgent #279`), SMP M (13 гео) |
| `Нагрузка L1` | BT M, агент 279, 23 гео, статусы депозитов и выводов |
| `Нагрузка Fraud` | статусы Fraud, порог 24 ч и больше |
| `Зависшие тикеты` | BT M / SMP M, затем API / API без L1 / PSP |
| `ЗТ по ГЕО BT M,SMP M,PSP` | зависшие от 24 ч и больше по гео, статусам и рефералам |
| `ЗТ по ГЕО API` | гео-таблица API / PSP со списком тикетов |
| `Сводная` | 5 чисел для промежуточных отчётов 12:00 и 19:00 |
| `Вечерний отчет` | текст вечернего отчёта, один столбец, одна кнопка |

3. Расставляет листы в порядке `Report`, `Фильтрация`, `Вечерний отчет`, `Сводная`, … . Все пороги «Nч+» считаются как `>= N`.
4. Кнопки «Копировать» вызывают `L2_CopyBlock` (адрес диапазона лежит в `AlternativeText` кнопки).

Общие вычисления BT M / SMP M делаются один раз в `L2_Btm_ComputeOnce`, результат хранится в переменных модуля `L2B_*`, `L2S_*`, `L2P_*`. Объявления стоят до первой процедуры, как требует VBA.

## Форматы исходных данных

Два макроса по сотрудникам читают лист `Sheet 1` с разной раскладкой, их нельзя менять местами:

| | `EmployeeEfficiency` | `EmployeeSwitches` |
|---|---|---|
| A | Команда | Стол |
| B | Стол | Имя |
| C | Имя | 1-е число, день |
| D… | 1-е число, день… | … |

В обоих случаях данные начинаются с 6-й строки, номер дня лежит в 4-й строке (в объединённых ячейках), тип смены («день»/«ночь») в 5-й.

## Зависимости и замечания

Замечания появились при первом чтении. Код я не менял.

1. **`CMB_CopyBlock` отсутствует.** Кнопка, которую создаёт `Monitoring_TTR_FTT`, вызывает `CMB_CopyBlock`, но ни в одной из трёх пачек его нет. Остальные модули используют свои обработчики с той же схемой (адрес диапазона в `AlternativeText` кнопки, `Application.Caller`), так что его можно написать по образцу, например `Monitoring_Выводы_CopyBlock`. Без него кнопка «Копировать» не сработает. Комментарий в `Monitoring_Load` («аналог `*_CMB` из `Общий_мониторинг_BT_M_SMP`») позволяет предположить, что он был в исходном отдельном макросе `Общий_мониторинг_BT_M_SMP`. Это предположение, в репозитории такого файла нет.
2. **`fillSwitchData()` отсутствует** (в трёх пачках).  `Monitoring_EmployeeSwitches` ссылается на «старый `fillSwitchData()`», который синхронизирует данные с этого листа. В репозитории его нет.
3. **`FixLatChars` в `Monitoring_TTR_FTT` объявлена как `Public`** и имеет общее имя. Если в проекте появится другая функция с таким именем, будет конфликт. Достаточно сделать её `Private` или переименовать.
4. **`Monitoring_TicketMovements` 1-го числа месяца.** Ширина сетки — `Day(Date) - 1`, то есть 0 столбцов. Лист получится пустым, а диапазон копирования в кнопках развернётся (`B:A`). Ошибки нет, но результат бесполезен. Также нет обработчика ошибок: при сбое `ScreenUpdating` остаётся выключенным.
5. **Комментарий про `B:AF` в `Monitoring_TicketMovements` устарел.** Реальный диапазон — `B..(MAX_DAYS+1)`.
6. **Пустая замена `Replace(s, "'", "'")`** в `NormalizeKey` и `CleanText` (`Monitoring_TicketMovements`) ничего не делает. Вероятно, изначально там был типографский апостроф `’`, и он потерялся при копировании. Если в данных встретится типографский апостроф, он не будет приведён к обычному.
7. **`Monitoring_EmployeeSwitches` без `Option Explicit`.** Остальные модули его используют.
8. **Жёстко зашитые значения.** Это листы `Sheet 1`, `Report` и «Второй лист», списки статусов (`Monitoring_StatusChains` с ID вроде `189`, `236`), стран, рефералов, цепочек, 58 строк в `Monitoring_AgentSwitches`, Agent ID `1014` (SMP) и `279` (BT M). При изменении наборов правьте массивы в коде.
9. **Все макросы пишут результат на свой лист.** Листы `Упорядоченный список`, `Преобразованные`, `Преобразованные данные`, `Маппинг_Цепочек`, `API`, `BT M`, `PSP`, `SMP`, `Filtered`, `Фильтр`, листы `72h+` и листы `Monitoring_Load` удаляются и создаются заново. Лист `Результат` очищается целиком (`Cells.Clear`). Не храните на этих листах ничего своего.
10. **Общие имена листов (актуально, только если запускать несколько макросов на одной книге).** `Результат` используют `Monitoring_StatusChains`, `Monitoring_AgentSwitches` и `Monitoring_Withdrawals`, `Filtered` создают `Monitoring_Filtering` и `Monitoring_SFP_SMP_NR72h`. Следующий запуск затирает лист предыдущего. Если каждый макрос запускается на своей выгрузке, проблемы нет.
11. **Разная точка отсчёта `Processing time`.** `Monitoring_Load` считает от максимальной `Processing date` в выгрузке, а `Monitoring_Filtering` и `Monitoring_SFP_SMP_NR72h` от `Now`. Из-за второго варианта пороги 72 ч и больше зависят от времени запуска, а в комментарии `Monitoring_Load` описано, что от такого расчёта там отказались.
12. **`Monitoring_API_BT_M_PSP_SMP` работает только на сырой выгрузке.** Он сравнивает `From` со значением `by customer`. На листе `Filtered` / `Фильтрация`, где `From` уже заменён на `User`/`PS`, все тикеты посчитаются как PS. Если для отдельного листа не нашлась нужная колонка (`Payment method` для API, `Agent` для SMP), этот лист не создаётся, а в конце макрос всё равно может показать «Готово!» (для SMP так и происходит).
13. **Неиспользуемый код в `Monitoring_Load`.** Процедуры `L2_Block_Leaders`, `L2_Block_BTM_PK`, `L2_Pk_PrintBlock`, `L2_Psp_WriteStatusRows`, `L2_Block_PSP_Geo` нигде не вызываются. Логика PSP-гео встроена в `L2_Block_BTM_SMP_Geo`, так что данные не теряются. Листы `Лидеры` и `Сводная таблица 12-19` макрос удаляет и упорядочивает, но не создаёт.
14. **`Monitoring_Filtering`.** В `MsgBox` строка начинается с `?`. Видимо, там был эмодзи, который потерялся при копировании. Нет `Option Explicit`.
15. **`Monitoring_AgentSwitches`.** Подсказка про вставку в Google Таблицу с `E11` зашита в сообщение. Названия стран и столов на листе `Результат` заданы в `BuildTargets`.
16. **Хранение и кнопки.** Имена публичных процедур во всех одиннадцати модулях уникальны, поэтому их можно держать вместе (например, в `PERSONAL.XLSB`), но это не обязательно: каждый модуль можно импортировать отдельно. Кнопки хранят в `OnAction` имя книги с кодом (`ThisWorkbook.Name`). В `Monitoring_Withdrawals` в комментарии прямо сказано, что это `PERSONAL.XLSB`. Если сохранить результат и открыть его на другом компьютере, кнопки без этой книги не сработают.
17. **`From` заменяется по-разному.** `Monitoring_Withdrawals` превращает `Through Customer Support` в `L1`, а `Monitoring_Filtering`, `Monitoring_SFP_SMP_NR72h` и `Monitoring_Load` в `PS`. Значение `By yourself` везде становится `User`.
18. **`Monitoring_Withdrawals`, кнопка Ticket ID отклонённых.** Если тикетов с `Transaction Status = rejected` нет, кнопка всё равно указывает на `K2`. Это первый Ticket ID из списка не отклонённых тикетов или пустая ячейка. Последняя строка данных определяется только по столбцу A, а при ошибке в середине макроса `ScreenUpdating` остаётся выключенным (обработчика ошибок нет).
19. **`Monitoring_Withdrawals`, геофильтр.** Он применяется только к четырём BT M-статусам (185 / 191 / 199 / 203). Статусы 238 / 205 / 175 и все SMP M-статусы считаются по всем странам.
